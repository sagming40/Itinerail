# 0003. 장소 검색은 국내 카카오 · 해외 Photon · 직접 입력, Google Places는 기본에서 뺌

- 상태: 채택
- 날짜: 2026-11-22

## 맥락

국내 + 해외 장소를 검색해 일정 카드에 붙여야 한다([0002](0002-travel-planner-topic.md)). 장소는 동선 · 돌아보기 · 정산에서 계속 쓰이니 **우리 DB에 우리 것으로** 두고 싶다. 공급자마다 할당량과 저장 규칙이 다르다 — 확인한 내용은 [REQUIREMENTS.md](../REQUIREMENTS.md) 3장(2026-11-22 공식 페이지).

## 결정

- **국내 = 카카오 로컬 키워드 검색**, **해외 = Photon**(OSM). 여행을 만들 때 고른 목적지(국내 / 해외)로 공급자를 정한다.
- 둘을 **Elixir behaviour 하나** 뒤에 둔다 — 공급자를 바꾸거나 더해도 화면 · 저장은 그대로다.
- **직접 입력은 늘 된다.**
- 장소는 이름(사용자가 확인 · 고칠 수 있게) · 공급자 · 공급자 ID · 위경도(있으면)로 저장한다. 추상 동선은 순서만 있으면 그려진다.

## 검토한 대안

- **Google Places (New)**: 해외 데이터는 가장 좋을 것 같지만, 정책이 **업체 이름 · 주소를 복사 · 저장하지 말라**고 한다(place_id만 무기한, 위경도는 30일). "우리 DB에 장소를 둔다"와 부딪히고, 지도 없이 보여 주면 Google Maps 로고 표시도 필요하다.
- **Nominatim (OSM 공식 공개 서버)**: 입력 중 자동 완성 용도로는 쓰지 말라는 사용 정책이 있다는 검색 결과를 봤다(정책 원문은 직접 읽지 않음). Photon이 자동 완성을 기능으로 내세워 그쪽을 골랐다.
- **Foursquare Places**: 무료 범위 설명이 공식 페이지끼리도 달라 확인을 못 했다.

## 감수할 것

- Photon 공개 서버는 숫자 한도가 없지만 "공정하게"만 적혀 있고 가용성을 보장하지 않는다. 많이 쓰게 되면 직접 띄워야 한다.
- 카카오가 해외 장소를 주는지, 저장 · 출처 표시 규칙(카카오맵 이용 정책)은 아직 모른다 — M4 전에 확인한다.
- 사용자가 고친 이름과 공급자의 원래 이름이 달라질 수 있다(일부러 그렇게 둔다).
- OSM 데이터 출처 표시(ODbL)를 화면 어딘가에 넣어야 할 것으로 본다 *(판단, 확인 전)*.
