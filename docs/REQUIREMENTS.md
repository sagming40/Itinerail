# 요구사항

> **무엇을 만들고 무엇을 만들지 않는지** 적는 문서다. 기능 번호와 우선순위, 외부 데이터 조건, 구현 전에 따라가 본 경우를 둔다.
> 진행 상황과 단계는 [PLAN.md](PLAN.md), 결정의 이유는 [decisions/](decisions/README.md).

## 1. 우선순위

**M**(첫 공개까지) / **S**(직후) / **L**(나중). 사용자 결정(2026-11-22): 국내 + 해외, 추상 동선으로 시작, 경비 정산 넣기.

### 하지 않을 것
- 예약 · 결제 · 송금 — 정산은 "누가 누구에게 얼마"를 **보여 주기만** 한다. 돈을 옮기지 않는다.
- 항공 · 숙소 가격 비교, 여행 상품 추천.
- 공개 여행 피드 · 좋아요 · 댓글 같은 소셜 기능.
- 장소 리뷰 · 평점 · 사진을 외부 공급자에서 가져와 보여 주기(저장 규칙 · 출처 표시 부담, 3장).
- 오프라인 편집 — LiveView 구조와 맞지 않는다. 연결이 끊기면 다시 붙을 때까지 편집을 막는다.
- 네이티브 앱.

## 3. 외부 데이터 — 장소 검색 (2026-11-22 공식 페이지 확인)

| 공급자 | 확인한 것 | 출처 |
|---|---|---|
| **카카오 로컬 — 키워드로 장소 검색** | 무료 **하루 100,000건**, 월 전체 API 3,000,000건. 넘으면 429, 유료 켜면 2원/건. "추후 변경될 수 있다". 한 번에 최대 15개 · 45쪽 · 반경 20km. **국내만인지, 저장 · 표시 규칙은 키워드 검색 절에 없다** — 링크된 "카카오맵 이용 정책"은 아직 안 읽음 | developers.kakao.com 쿼터 · 로컬 개발 가이드 |
| **Google Places API (New)** | Autocomplete 월 10,000건 무료(그 뒤 1,000건당 $2.83), Place Details Essentials(IDs only) · Text Search Essentials(IDs only) 무료 무제한, Text Search Pro 월 5,000건. **place_id는 무기한 저장 가능, 위경도는 30일까지만 캐시, 업체 이름 · 주소는 복사 · 저장하지 말 것**. 구글 지도 없이 보여 주면 "Google Maps" 로고 · 글자 표시 필수 | Google Maps Platform 요금 · Places 정책 |
| **Photon** (komoot, OSM 기반) | 공개 서버는 "합리적인 양이면 써도 된다, 많이 쓰면 제한 · 차단, 가용성 보장 없음". 숫자 한도는 없다. 검색어 입력 중 자동 완성(typeahead)을 기능으로 내세운다. 소프트웨어 Apache-2.0, 많이 쓰면 직접 띄우라고 권한다. POI(식당 · 카페) 범위와 데이터 라이선스 · 출처 표시는 README에 명시 없음 | github.com/komoot/photon · photon.komoot.io |

정한 것은 [decisions/0003](decisions/0003-place-search-providers.md) — 국내 카카오 · 해외 Photon · 직접 입력, Google은 기본에서 뺌. 그 결정에서 나온 요구:
- 장소는 우리 DB에 우리 것으로 저장한다: 이름(사용자가 확인 · 고칠 수 있게), 공급자 · 그 공급자의 ID, 위경도(있으면). 추상 동선은 순서만 있으면 그려진다.
- 직접 입력(이름만)은 늘 된다 — 검색이 막혀도(429 · 차단 · 장애) 일정을 짠다.
- 공급자 호출은 서버에서만, 입력이 멈춘 뒤에만(디바운스), 같은 검색어는 잠깐 캐시 — 카카오 짧은 시간 호출 제한(숫자 비공개)과 Photon "공정하게"를 지키려고.

**M4 전에 확인할 것**: 카카오맵 이용 정책(저장 · 출처 표시), 카카오 키워드 검색이 해외 장소를 주는지, Photon 결과의 한국 · 해외 POI 품질(직접 몇 군데 검색), OSM 데이터 출처 표시 방법(ODbL — 아직 확인 안 함).

## 4. 사전 검증에서 본 경우 (초안)

구현을 마쳤다고 치고 따라가 본 경우다. 단계마다 테스트로 옮긴다.

- **두 기기 동시 편집** (이 앱의 시험 문제): A가 카드를 2일 → 3일로 옮기는 순간 B가 같은 카드 메모를 고친다 → 둘 다 여행 프로세스를 한 줄로 지나가니 둘 다 반영된다. A가 카드를 지우는 순간 B가 그 카드를 고친다 → 뒤에 온 요청이 "없는 카드"로 거절되고 B 화면에 알림. 같은 순서 번호를 두 사람이 동시에 차지 → 프로세스가 번호를 다시 매겨 뿌린다 *(판단)*.
- **프로세스가 죽으면**: 편집은 DB에 쓰고 나서 확정으로 보고 뿌린다 → 프로세스가 다시 뜨면 DB에서 읽어 이어 간다. 배포(재시작) 중 편집은 연결이 끊긴 것으로 보고 다시 붙으면 최신 상태를 다시 그린다 *(판단 — M3에서 확인)*.
- **남의 데이터**: 여행 ID를 바꿔 넣기, 초대 링크 재사용 · 남에게 전달, 내보내진 멤버가 열어 둔 화면에서 계속 편집 → 모든 편집 요청마다 멤버 · 역할을 다시 확인한다(화면을 연 순간만 보지 않는다).
- **비로그인**: 초대 메일 링크를 로그인 안 한 사람이 누름 → 가입 · 로그인 뒤 초대 수락으로 이어진다. 초대 만료 · 이미 수락함 · 메일 주소가 다른 계정으로 로그인함.
- **빈 값 · 0건 · 범위 밖**: 장소 없는 날, 카드 하나뿐인 동선(선 없음), 기간을 줄여 카드가 있는 날이 사라짐(지우지 말고 "날짜 밖" 칸으로), 0원 지출, 나 혼자인 여행의 정산.
- **시간대**: 해외 여행은 현지 시각으로 일정을 적는다 → 카드 시간은 "그 여행 날짜의 현지 시각"으로 저장하고 시간대는 여행(또는 날짜)에 둔다. D-1 메일은 받는 사람 기준 KST *(판단)*. 날짜 변경선을 넘는 일정.
- **통화 · 반올림**: JPY처럼 소수 없는 통화, 1원 나머지, 환율 미입력 지출(정산에서 빼고 경고).
- **외부 실패**: 카카오 429 · 짧은 시간 제한, Photon 차단 · 느림 → 시간 초과를 짧게, 직접 입력으로 계속.
